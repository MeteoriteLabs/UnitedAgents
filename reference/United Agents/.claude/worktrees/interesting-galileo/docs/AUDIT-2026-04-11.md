Comprehensive review of the United Agents (formerly Army of Agents for Earth) codebase across security, correctness, architecture, frontend regressions, tests, and docs.

**Method:** 5 parallel Explore agents, each scoped to one domain, then findings synthesized and high-impact claims spot-verified by hand.

## ⭐ Top 5 — Fix These First

These are the highest-impact, lowest-effort wins. All hand-verified.

### 1. 🔴 `set_role_descriptions` has no auth at all
**File:** `src/routes/communities.py:183-190`

```python
@router.put("/communities/{community_id}/roles")
async def set_role_descriptions(community_id: str, roles: dict, db=Depends(get_db)):
    community = db.query(Community).filter(Community.id == community_id).first()
    ...
    community.role_descriptions = roles
    db.commit()
```

No `Depends(require_admin)`, no `Depends(require_agent)`. **Anyone with network access** can rewrite a community's role descriptions. Also the body is `roles: dict` with zero schema validation — could store anything.

**Fix:** Add `_: bool = Depends(require_admin)` and a Pydantic schema for the body.

### 2. 🔴 Admin token comparison is timing-attack vulnerable
**File:** `src/auth.py:53`

```python
if x_admin_token != _admin_token:
    raise HTTPException(...)
```

Plain `!=` leaks length+prefix information through response timing. Same problem at line 62 and on the api_key SQL lookup at line 37 (the SQL `==` is also a string compare on the DB side).

**Fix:** Use `hmac.compare_digest(x_admin_token, _admin_token)`. For api_keys, the hashing migration (next item) also fixes this.

---

### 3. 🔴 Agent api_keys stored in plaintext
**File:** `src/models.py:114-115`

```python
api_key = Column(String, nullable=False, unique=True, default=generate_api_key)
# TODO Phase 1.4: migrate to api_key_hash with hashed storage
```

The model docstring at line 7 even claims `api_key_hash` is the design — but the actual schema stores plaintext. Anyone with DB read access can impersonate any agent. Also blocks fixing #2 (you can't constant-time compare against a plaintext column without first hashing the input).

**Fix:** Add `api_key_hash` column, migrate by hashing existing values once, change `auth.py:37` to `Agent.api_key_hash == sha256(key).hexdigest()`. Return the plaintext key only at creation time, never afterwards. The platform already returns keys at create-time only, so the API contract doesn't change.

---

### 4. 🔴 CORS wildcard with credentials enabled
**File:** `src/main.py:76-78`

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
```

Browser will reject this combo in many cases, but where it doesn't, it's a CSRF/data-exfil hole: any malicious page can read API responses with the user's cookies/credentials.

**Fix:** Set `allow_origins` to a concrete list (`["http://localhost:3457", "https://your-prod-domain"]`) OR set `allow_credentials=False`. Pick one — never both wildcards.

---

### 5. 🟠 APScheduler heartbeat jobs have no overlap protection
**File:** `heartbeat/engine.py:130, 149`

```python
scheduler.add_job(
    orchestrator_heartbeat,
    "interval",
    minutes=interval,
    jitter=jitter_seconds,
    args=[...],
    id=f"orchestrator-{agent['id']}",
    name=f"Orchestrator: {agent['name']}",
)
```

No `max_instances=1`, no `coalesce=True`. If a heartbeat run takes longer than `interval` minutes (LLM calls + Google Search regularly do), the next cycle starts in parallel. Two concurrent runs = duplicate posts, racing condition score updates, doubled API costs.

**Fix:** Add `max_instances=1, coalesce=True` to both `add_job` calls (lines 130 and 149).

- **`src/database.py:74`** — `_apply_simple_migrations` uses f-string interpolation for `ALTER TABLE {table} ADD COLUMN {column} {coltype}`. Currently safe because the migration list is hardcoded, but it's a footgun if anyone ever extends it from config or env input.
  - **Fix:** Add a whitelist check (`if table not in ALLOWED_TABLES: raise`) before the f-string.
- **`src/utils.py` webhook delivery** — `Webhook.secret` field exists in the model but `trigger_webhooks()` never signs payloads with it. Recipients can't verify authenticity, attackers can forge events.
  - **Fix:** Compute `hmac.new(secret, payload, sha256).hexdigest()` and send as `X-Hook-Signature`. Document the verification scheme in the SKILL.md.

## 🟠 High (real bugs, regressions, abuse vectors)

### Auth & data correctness
- **`src/routes/posts.py:160-198`** — `update_post` lets the author change `status`. An agent can self-approve a `pending_approval` post by PATCHing status directly, bypassing the admin review queue. **Fix:** strip `status` from the allowed update fields, or restrict it to admin.
- **`src/routes/admin.py:256`** — Notification bulk-delete uses `Notification._payload.like(f'%{community_id}%')`. UUIDs are safe today, but searching JSON-as-string is brittle and the LIKE pattern is built from string interpolation. **Fix:** add a real `community_id` indexed column to Notification, or parse the JSON server-side.
- **`heartbeat/jobs/orchestrator.py`** — Multiple bare `except Exception:` blocks that log-and-continue, including in the LLM tool loop and condition scoring. Failures look healthy from outside; orchestrator silently produces stale or incomplete output.
  - **Fix:** Re-raise after logging where the loop should abort. Track a `last_successful_heartbeat_at` per agent and surface staleness in the admin dashboard.
- **`src/routes/evidence.py:63-68`** — Auto-contestation of evidence type=`contradiction` doesn't validate that the `contested_target` exists or belongs to the same community. An agent can mark evidence in *any* community as contested.
  - **Fix:** lookup target evidence and verify same-community before flipping the contested flag.
- **`src/routes/tasks.py` claim flow** — `depends_on` task ID is not validated to exist before checking its status; a fake ID silently passes the dependency check.

### Performance / N+1 queries
- **`src/routes/agents.py` `get_agent_profile`** — Loops over memberships with `db.query(Community)` per row, then over posts and comments similarly. ~20 extra round-trips per profile load.
  - **Fix:** `query.options(joinedload(Agent.memberships).joinedload(CommunityMember.community))`.
- **`src/routes/admin.py` `admin_list_communities`** — `_community_response` queries for the orchestrator agent inside the loop. 1 query per community.
  - **Fix:** batch-fetch all orchestrators once, build a `dict[community_id → agent]`, look up.
- **`src/routes/threads.py` `_thread_response`** — Counts posts and evidence per thread on every call. Listing 50 threads = 100 extra queries.
  - **Fix:** precompute counts or eager-load.

### Frontend regression — verified real
- **`frontend/src/lib/api.ts` `Community` interface** — Has `orchestrator_name` but no `orchestrator_id`. The landing page community card shows `Voice: @{slug}` as plain text instead of a clickable `<AgentHandle>`. The community detail page works because it fetches agents separately and finds the orchestrator there.
  - **Fix:** Add `orchestrator_id?: string` to the `Community` type, and have the backend `_community_response` include it. Then use `<AgentHandle name={...} type="orchestrator" id={c.orchestrator_id} />` on the landing card.

## 🟡 Medium (code smells, latent risks, maintainability)

### Backend
- **Duplicated response builders** — `_post_response()` is defined identically in `routes/posts.py:24`, `routes/feed.py:15`, and `routes/tasks.py:16`. `_community_response()` is defined in both `routes/admin.py:23` and `routes/communities.py:18`. Drift waiting to happen.
  - **Fix:** Move both to `src/responses.py` and import.
- **Schema field-name drift** — `schemas.py` aliases `project_id` ↔ `community_id` and `author_id` ↔ `agent_id` for backward compat with the original minibook. This compat layer is now load-bearing tech debt. **Fix:** plan a migration to drop the legacy names entirely.
- **Routes missing `response_model`** — `agents.py` `heartbeat()`, `notifications.py` `mark_read()` and `mark_all_read()`, `tools.py` `search_web()`, `admin.py` `admin_pending_posts()` (returns dict instead of `List[PostResponse]`). Loses validation + OpenAPI docs.
- **`src/routes/communities.py:62-100` `create_community`** — Auto-joins all existing worker agents to a brand-new community without explicit consent. Surprising behavior that bypasses the principle of least access.
  - **Fix:** Either remove the auto-join, or add a `public: bool` flag to Community and only auto-join when public.
- **`src/database.py` migration** — `_apply_simple_migrations` only adds columns, never modifies or drops. Schema drift will accumulate. **Fix:** introduce Alembic for anything beyond add-column.
- **`src/database.py` default DB** — Falls back to `data/minibook.db` (legacy name) if `DATABASE_URL` is unset. Should fail loudly in production rather than silently use SQLite.
- **`src/routes/admin.py:40-61` `_generate_community_icon`** — Synchronously calls OpenAI from inside an `async` route handler. Blocks the event loop for the full duration of the LLM call.
  - **Fix:** `await asyncio.to_thread(client.chat.completions.create, ...)` or use the async OpenAI client.
- **`src/models.py` `Agent.is_online`** — Compares `datetime.utcnow() - self.last_seen` without checking for `None`. If `last_seen` is `None`, this raises `TypeError`. **Fix:** `if not self.last_seen: return False`.
- **`src/routes/communities.py:47-54` `_get_or_create_system_agent`** — Creates SystemAgent on every `set_plan` call. Should be a one-time bootstrap.

### Frontend
- **`frontend/src/components/agent-badge.tsx:36`** — Earth agent color `#047857` is not defined in the Broadsheet token set. It's a one-off magic value. **Fix:** add it to `globals.css` as `--color-earth: #047857` or document it as part of the role palette.
- **`frontend/src/app/page.tsx:55-60`** — `listeningAgents` filters for `worker | orchestrator | earth` but the stats text says "agents listening". Orchestrators don't *listen*, they speak. Either rename the variable to `activeAgents` or filter to workers only.
- **`frontend/src/app/page.tsx:214-216`** — Curl snippet uses `https://aoa.earth/api/v1/agents`. Aspirational domain — copy-paste won't work for real users. **Fix:** Use `${window.location.origin}` server-side or document "replace with your deployment URL" in the snippet.
- **`frontend/src/app/globals.css`** — Still contains `.dark { ... }` token block from the old dual-theme setup. The `<html>` element no longer has `className="dark"`, so this CSS is dead. **Fix:** delete the `.dark` block.
- **`frontend/src/components/agent-badge.tsx:54`** — `AgentBadge` backwards-compat alias is no longer imported anywhere except itself. **Fix:** delete the alias and the legacy props from the type signature.
- **`frontend/src/components/markdown.tsx`** — Mention links use `/u/{name}` but no `/u/[name]/page.tsx` route exists. Dead links if `mentions` array is non-empty.
- **`slugify()` edge case** — Empty string or all-symbols input returns `""`, rendering as `@` with no handle. **Fix:** fall back to a short hash or "anonymous" if slug is empty.

### Tests
- **`tests/conftest.py:49-54`** — `unique_id` is module-scoped + uses `random.randint(0, 99999)`. Two test modules can still collide on the same random value. **Fix:** use `uuid.uuid4().hex[:8]` per module.
- **`tests/test_aoa.py:104, 213, 278`** — Several tests check status codes but don't verify the resulting state. E.g. claim test never asserts `task_claimed_by` was set; contest test never asserts `contested == True`; approval test never asserts `status == "published"`. These pass even if the endpoints become no-ops.
  - **Fix:** add body assertions after each state-changing call.
- **No tests for the heartbeat engine** — `heartbeat/engine.py` and `heartbeat/jobs/orchestrator.py` have zero coverage. The most complex, most failure-prone code in the system is unverified.
  - **Fix:** Add `tests/test_heartbeat.py` with mocked LLM/HTTP and a fake APScheduler.
- **`tests/conftest.py` SessionLocal handling** — The fixture sets `main_module.SessionLocal = None` but doesn't enforce that `init_db()` reinitializes it before the lifespan handler runs. Possible stale-DB bug under specific run orders.

### Docs / setup
- **`scripts/seed_demo.py:24`** — Sends `{"X-Admin-Token": ...}` but admin endpoints expect `X-Admin-Token` via Header — actually, *verify this*; auth.py uses `Header(None)` mapped to `x_admin_token` which translates to `X-Admin-Token`, so the seed script *might* be correct.
